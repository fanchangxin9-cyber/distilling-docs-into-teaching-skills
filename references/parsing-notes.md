## 先判断文字层能不能用

`convert_to_markdown.py` 对每页做两道检查，任一不过就渲染成 200dpi PNG 并列入 `needs_vision`：

| 检查 | 判据 | 标记 |
|------|------|------|
| 有没有字 | 非空白字符数 < 25 | `no_text_layer` |
| 字是不是真的 | 可疑字符占比 > 10% | `garbled_text` |

**第二道比第一道更重要，也更容易被忽略。** 有些 PDF 有文字层，但嵌入字体缺少 ToUnicode 映射，抽出来全是错码 —— 看起来是字，读起来是 `*eòe¢H:AIöã—`。

**判据就是上面表格里那一条**：落在 Latin-1 补充区（`U+0080–U+02FF`）和私用区（`U+E000–U+F8FF`）的字符**占比超过 10%**，就认定文字层不可用。（脚本不额外判断"中文占比"——只算这一个比例，见 `convert_to_markdown.py` 的 `GARBLED_THRESHOLD`。）

**不要试图清洗这类乱码，也不要把它当噪声删掉 —— 直接整页走视觉。** 这类文档（课件、PPT 导出、设计排版过的宣传册）通常排版本身就是内容，视觉读反而更完整。需要时可加 `--render-all` 整篇渲染。

拿到结果后：

- `status: "ok"` 且 `needs_vision` 为空 → 读 `.distill/<slug>.md`
- `needs_vision` 非空 → 用 **Read 工具**读 `vision_files` 里列的图片，**同页抽取出的文字一律不要**

**不要**对扫描件盲目相信 OCR 类抽取结果 —— 视觉模型直接看图通常更准。

## PDF

| 问题 | 表现 | 处理 |
|------|------|------|
| **多栏排版** | 抽出的文本左右栏交错、语无伦次 | 改用 `get_text("blocks")` 按坐标分区，或直接渲染成图走视觉 |
| **页眉页脚** | 每页重复的相同行 | 识别重复行并删除，别让它淹没有效内容 |
| **表格** | 单元格错位、行列丢失 | 脚本只做基础处理；**表格重要时直接视觉读那一页** |
| **文字层乱码** | 抽出的字符大量落在 Latin-1 补充区/私用区（如 `öã—åñ`） | 嵌入字体缺 ToUnicode 映射。**别清洗、别当噪声删，整页走视觉** |
| **加密** | `fitz.open` 抛异常 | 让用户提供密码，或另存为无密码版本 |
| **目录/书签** | —— | `doc.get_toc()` 能拿到大纲，**对理解文档结构很有帮助，值得单独看一眼** |

## Word docx

- **文本框、形状里的文字**：`python-docx` 的段落遍历**取不到**。发现内容明显缺失时，用 `unzip` 解出 `word/document.xml`，搜 `w:txbxContent`。
- **批注与修订**：不在正文流里，需另解 `word/comments.xml`。合同、规范类文档里的批注往往是关键判据，值得单独抽。
- **旧版 `.doc`**：`python-docx` 不支持，脚本会返回 `unsupported` → 让用户另存为 `.docx` 或 PDF。
- **内嵌图片里的文字**：和 PDF 扫描页一样，走视觉。

## 图片与截图

- **该用视觉的信号**：界面截图、表格图片、流程图、手写批注 —— 直接看图比任何文字抽取都准。
- **长截图**：分辨率高且内容密集时视觉会漏细节。提示用户分段截，或先切成多张再逐张读。
- **清晰度**：默认 200dpi；整页 A4 密排小字用 300dpi。
- **UI 截图**：注意区分"按钮文字"和"正文内容"。按钮文字（"提交"、"导出"）通常正是要保留的操作细节，别当噪声删了。

## 缓存与增量

`.distill/` 的结构：

```
.distill/
├── <slug>.md      抽取结果（含 source / sha256 头注释）
├── <slug>.json    元数据：source / size / mtime / sha256 / needs_vision / vision_files
└── pages/         扫描页渲染出的 PNG
```

`<slug>` = 文件名清理后的 stem + **源路径**的 sha256 前 8 位。这样同一文件改名后仍能对应，而不同目录下的同名文件不会撞车。

增量判断规则：

- **比对 `sha256`，不要比对 `mtime`** —— 复制、同步、解压都会改 mtime 但不改内容
- 源文件 sha256 没变 → 脚本返回 `cached`，跳过重解析
- 源文件被删除、但 `.distill/` 里还留着记录 → **明确告诉用户**，不要默默继续
- 用户说"文档改了，更新一下"→ 重跑解析，只重建 sha256 变化的文档对应的 Skill
