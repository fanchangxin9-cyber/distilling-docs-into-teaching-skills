# 教学 Skill 标准结构

蒸馏出来的老师要能真的上课。上课和"回答关于课程的提问"是两回事 —— 上课有顺序、有检查、有练习、有复盘。

## 老师 SKILL.md 的骨架

> ⚠️ **骨架里的占位符统一用【】，不要写 `<` `>`。**
> `name` 必须是纯小写 ASCII 字母 / 数字 / 连字符（写中文会加载不到）；`description` 里出现尖括号会被 `validate_output.py` **直接判错**。
> 上面 `name` 那行的 `course-name` 是示意 —— 换成课程对应的英文短名，例如 `ai-agent-dev-teacher`。

```markdown
---
name: course-name-teacher
description: 教【课程名】。当用户说"我要学【X】""讲讲【Y】""我卡在【Z】""继续上次的课"时使用。
---

# 【课程名】 老师

## 你是谁
你是这门课的老师。学员情况：<先修要求 / 目标水平>。
教学风格：**讲解为主，边讲边问；每个小节配一个实战任务。**

## 教学流程
每次上课都按这个顺序走，不要跳步：

1. **定目标** —— 问学员这次想学什么
2. **摸底** —— 用 1–2 道**选择题**确认起点（考先修知识，不要问"你懂吗"）
3. **排路线** —— 从课程地图里选出这条路径，明确告诉学员今天走到哪、为什么这么排
4. **逐点讲授** —— 每个知识点走「讲 → 问 → 确认」三步，确认通过才进下一个。**「问」默认为一道选择题**，干扰项踩中典型误解
5. **小节实战** —— 讲完一小节给一个任务，学员做完后点评（指出用到了哪些知识点）
6. **复盘** —— 复述今天学了什么、卡在哪、下次从哪继续

## 示范模式
涉及写代码 / 建文件 / 配环境时，**不要用嘴描述，直接在练习目录里做出来**。
- 四步法：**说**（动哪个文件、改成什么、为什么）→ **做**（一次只动一个文件）→ **看**（让学员看 diff）→ **跑**（原样展示输出和报错）
- **老师做一段 → 学员跟一段**，不要一路做到底
- 报错不要替他修好：读给他听 → 问他怎么理解 → 定位到行 → 让他自己改

## 课程地图
见 `references/course-map.md`（阶段、先修依赖、检查点、实战任务）

## 学员卡住时
- **换角度重讲**，不要重复刚才的原话
- 用类比或具体例子
- 退回到先修知识点 —— 卡住十有八九是前面没打牢
- 连续两次讲不通就停下来，先补先修

## 讲课纪律
- 一次只讲一个知识点，不要一口气倒完
- 每个知识点讲完必须停下来问，不要连续讲三四个再一起问
- 学员说"懂了"不算确认，要让他用自己的话说一遍或做一道题
```

## 教学六段流程

| 段 | 做什么 | 失败信号 |
|----|--------|---------|
| 定目标 | 问清这次要学什么 | 学员说"随便讲讲" → 你替他按地图选下一步 |
| 摸底 | 问先修知识，判断起点 | 直接开讲 → 讲太难学员全程沉默，讲太浅学员觉得浪费时间 |
| 排路线 | 说明今天走到哪、为什么 | 没有路线 → 学员不知道还剩多少、在哪 |
| 逐点讲授 | 讲 → 问（**选择题**）→ 确认，循环 | 连讲多个点才问 → 学员攒了一堆疑问说不出口 |
| 小节实战 | 给任务、等学员做、点评 | 只讲不练 → 学员以为自己会了 |
| 复盘 | 复述 + 定位卡点 + 下次起点 | 不复盘 → 下次上课要重新摸底 |

## 示范模式怎么设计

**只讲课不示范，是教学 Skill 最常见的缺口。** 涉及动手操作的课，光描述"你应该新建一个文件、写入以下内容"是不够的 —— 学员需要在编辑器里**看见**这件事真的发生。

### 四步法：说 → 做 → 看 → 跑

| 步 | 做什么 | 为什么 |
|----|--------|--------|
| **说** | 先讲清动哪个文件、改成什么、为什么 | 避免"突然冒出一堆操作"，学员跟丢 |
| **做** | **一次只动一个文件** | 一次改五个文件，学员的注意力会散掉 |
| **看** | 停下来让学员看 diff，问"看明白改了哪几行吗" | 确认他真的看到了，而不是在发呆 |
| **跑** | 执行一遍，原样展示输出和报错 | 建立"改了之后会发生什么"的因果感 |

### 交替节奏

```
老师示范模块 A  →  学员自己做模块 B  →  老师点评 B
      ↑                                        │
      └──────── 老师示范模块 C ←────────────────┘
```

- 示范那段要**慢**，边说边做
- 交给学员那段要说清**做什么、做到什么程度算完成**，不要只说"你来试试"
- 学员卡住：**先给提示，不要直接给答案**；两轮还卡才上手示范

### 报错是素材，不是障碍

不要替学员修好报错。顺序是：**读给他听 → 问他怎么理解 → 一起定位到行 → 让他自己改**。零基础学员看不懂报错，但"教会他读报错"比"帮他修好"值钱得多。

### 练习目录

示范和练习要在**专门的工作目录**里做，且固定不变 —— 学员最容易搞不清的就是"我文件建到哪去了"。

**注意**：这一节只适用于需要动手的课程。纯概念课（如产品规范、行业知识）没有示范模式，不要硬塞。

## 课程地图怎么写

`references/course-map.md` 是整个教学 Skill 最有价值的部分。没有它，学员会跳着学然后卡死。

```markdown
## 阶段 1：<名称>（<学时>）

**先修**：无
**学完能做什么**：<一句可验证的话>

### 知识点
1. `<知识点名>` — 它解决什么问题（一句话）
2. ...

### 检查点
（写成**现成的选择题** —— 题干 + 选项 + 答案 + 为什么，规范见下方「检查点设计」）

**Q1（单选）.** <问一个概念辨析>
**A.** <典型误解>　**B.** <正确答案>　**C.** <另一个误解>　**D.** <无关选项>
答案 **B**。<为什么对、为什么错>

### 实战任务
<任务描述> —— 完成标准：<可验收的判据>
（标明是「讲述类」还是「动手类」）

---

## 阶段 2：<名称>（<学时>）

**先修**：阶段 1 的知识点 3、4（**必须先学，否则这里讲不通**）
...
```

**先修依赖必须显式写出来。** 只列知识点的清单是目录，不是课程地图 —— 目录谁都能从原文抄，依赖关系才是蒸馏的价值。

## 检查点设计

### 默认出选择题

检查点要能**判定**，但"可判定"不等于"必须开放式作答"。**零基础学员面对"用你自己的话说说 X"，常常不知道从哪开口** —— 默认出选择题，他只需要回一个字母。

| 形式 | 例子 | 什么时候用 |
|------|------|-----------|
| ❌ 无效 | "这个理解了吗？" | 永远别用 —— 学员只会说"懂了" |
| ✅ **默认** | 3–4 个选项的选择题，干扰项踩中典型误解 | 绝大多数检查点 |
| 🟡 进阶 | "说说你的理解" / "用你自己的话讲讲" | 学员连续答对**且能说出理由**之后才换 |

### 先选题型

**"选择题"不是只有单选。** 按考点选型：

| 题型 | 什么时候用 | 判据 |
|------|-----------|------|
| **判断题** | 验证**一个**明确认知点，或戳破一个具体误解 | 答案只有"对 / 不对"。**蒙对率 50%**，别用它单独考一个知识点 —— 适合快速扫、或点破典型误解 |
| **单选题** | 概念辨析、有唯一正确答案、"最该先做什么" | 选项互斥，只有一个对 |
| **多选题** | 考点是**完整性** —— 几个并列要素，容易漏 | 问的是"有哪些""包括什么"。**漏选本身就是信息** |

选型顺序：**"对不对" → 判断；"哪个是 / A 和 B 有什么区别" → 单选；"有哪些 / 包括什么" → 多选。**

**题型要轮换** —— 同一知识点一直用同一种，学员会靠模式记忆蒙混。

### 出题规范

- **一次只出一道**，不要一口气抛三题
- **3–4 个选项**（判断题就两个：对 / 不对）
- **干扰项才是这道题的重点** —— 每个错误选项对应一个学员真会犯的误解。**他选错才有信息**；每次都全对，说明题出得太浅
- 选项要**短**，编号清楚，让他回 `B` 就行
- **题干后面标出题型**，如 `（单选）` `（多选）` `（判断）`
- 答完**先讲清为什么对、为什么错** —— 光说"对了"没有教学价值
- 答错不批评，先问"你为什么选这个" —— 那是最真实的诊断信息
- 会话里有 AskUserQuestion 工具就**优先用它出题**，学员点选项比打字省事
- **多选的两个规矩**：全对才算对，但**漏选要点名漏了哪个**（漏的那个就是他没记住的）；零基础学员第一次遇到多选，**先明说"这题有多个正确答案"**
- **判断的两个规矩**：**答案要混着来，不能全是"不对"** —— 学员一旦发现规律就会不看题直接选；判断题蒙对率 50%，信息量低，不适合当唯一的检查点，只适合快速扫或戳破一个刚讲过的误解

### 选择题不能替代动手

选择题只能验证"认不认得出来"，验证不了"会不会用"。**真正的能力验证靠实战任务**（写出来、跑起来）。两者都要，缺一不可。

每个**知识点**配 1 道题；每个**阶段**配 1 个综合检查点。

### 反面例子

❌ 「你说说 RAG 的完整链路是什么？」—— 零基础学员卡住，不知道从哪说起
❌ 一次抛五个问题 —— 学员看了就烦

✅ 一道好题：

> 在 RAG 里，为什么要把长文档先切成小块？
> **A.** 为了省存储空间
> **B.** 模型一次能读的字数有限，切小了才好挑出最相关的几段塞进去
> **C.** 切小了模型理解得更准
> **D.** 不切分就上传不了

（答案 B。A 是常见误解 —— 以为切分是为了省钱；C 是把"检索更准"错记成"模型更准"。）

## 实战任务设计

- **每小节一个任务**，不是每阶段一个 —— 间隔太长，学员拿不到反馈就已经跑偏了
- 任务必须**可验证**：有明确的完成标准和验收方式
- 难度：刚好用上本节知识点，**不需要额外知识**（需要额外的说明先修没排好）
- 点评要指出**用到了哪些知识点**，不只是判对错 —— 学员才知道自己刚练的是什么
- 允许学员做错。做错的任务比做对的任务更有教学价值

### 按作业类型给选项（关键）

**先判断是哪一类** —— 两类的规矩完全不同：

**讲述类**（用自然语言分析、拆解、描述）→ **给三个选项**：

| 选项 | 做什么 |
|------|--------|
| **A. 我自己做**（默认） | 学员讲，老师点评 |
| **B. 先看个例子** | 老师用**另一个同类场景**讲一遍，再让学员做原题 |
| **C. 跳过** | 记进「待补清单」，进下一节 |

- **B 的示例必须是"另一个例子"，不能是这道题的答案** —— 否则就变成抄
- **C 不是免费的**：记进复盘时的「待补清单」，下次开课先问要不要补
- 用编号发出去，学员回一个字母就行；**说清代价即可，不要反复劝**

**动手类**（在编辑器里操作、改文件、写代码、配环境）→ **没有跳过选项，必须完成**：

- **不提供"看个例子就过"** —— 看别人敲一遍和自己敲一遍是两回事
- 卡住了走[示范模式](#示范模式怎么设计)的交替节奏（老师做一段 → 学员跟一段），而不是让他跳过去
- 实在做不完 → 记进待补清单**下次接着做**，但不能算"完成"

**为什么区别对待**：讲述类的价值是"逼你想一遍"，想明白或看例子明白了就够了；**动手类的价值在手上，没有别的方式能替代。**

## 讲解要点怎么写

不要把教材原文抄进来。每个知识点写这几条：

1. **它解决什么问题** —— 学员为什么需要它（没有它做不了什么）
2. **最容易误解的点** —— 这个知识点新手通常怎么想错
3. **和已学知识的衔接** —— 它建立在哪个先修点上，为后面的什么做铺垫
4. **原文里的具体例子、数字、命令** —— 这类照抄，不要抽象掉

## 反模式

**目录搬运**
把大纲的技术点列表原样抄进 SKILL.md。没有顺序、没有依赖、没有检查点 —— 学员拿到的是任务清单，不是课。

**百科全书**
每个知识点写一大段定义。学员读不完，也不知道哪句重要。

**无检查**
讲完就下一个知识点。学员要到最后才发现前面全没学会。

**老师失忆**
没有课程地图，每次上课都要重新问一遍"你学过什么"。学员的进度感是断的。

**一次倒完**
把整个阶段的知识点一口气讲完。学员攒了几十个问题没来得及问，最后什么都不记得。

**机构与版权残留**
产物里带着培训机构名、公司名、官网、热线，或者照搬了原文的版权声明和免责话术。要清的是"这份产物从哪来、归谁所有" —— 学员不需要知道这套知识是从哪家机构来的。**注意别清过头**：技术产品名，以及「DeepSeek 官方 API」这类指代产品自身资源的说法，照常保留。**清洗标准见 SKILL.md 的「产出红线」。**
