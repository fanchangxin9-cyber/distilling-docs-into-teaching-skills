# 产出的 SKILL.md 写作规范

蒸馏出来的 Skill 要能被 Claude 正确加载和触发，必须满足下面这些硬性约束。

## frontmatter 硬性约束

```yaml
---
name: skill-name
description: 一句话说明做什么 + 什么时候用
---
```

| 字段 | 约束 |
|------|------|
| `name` | 小写字母 / 数字 / 连字符；≤64 字符；**必须与目录名一致**；不能以连字符开头结尾，不能有连续连字符 |
| `description` | ≤1024 字符；**不能包含尖括号 `<` `>`**；第三人称 |
| 其他 key | 只允许 `license`、`allowed-tools`、`metadata`，多写会被校验拒绝 |

命名优先用**动名词**：`processing-pdfs`、`distilling-docs-into-skills`、`analyzing-logs`。
避免 `helper`、`utils`、`tools` 这类看不出干什么的名字。

**教学 Skill 是例外**：用 `<课程名>-teacher`（如 `ai-agent-dev-teacher`）—— 它的身份是"这门课的老师"，不是一个动作，硬套动名词反而别扭。

⚠️ **`name` 只能是小写 ASCII 字母 / 数字 / 连字符**，不能写中文。课程名是中文时（如《AI应用与智能体开发》），起一个对应的**英文短名**（`ai-agent-dev-teacher`）。

## description 写法

三要素：**做什么 + 什么时候用 + 用户会说的关键词**。

✅ 好例子：
> 把 PDF、Word 文档和图片里的知识蒸馏成可复用的 Claude Skill。当用户提供文档并要求"做成 skill""提炼成 skill"，或提到 SOP、操作手册需要转成 Skill 时使用。

✅ 另一个：
> 处理 Excel 表格并生成汇总报表。当用户提到 Excel、CSV、数据汇总、透视表时使用。

❌ 坏例子：
- `我帮你处理文档` —— 第一人称，且没说什么时候用
- `文档处理工具` —— 太宽，几乎什么都触发
- `用于处理用户上传的各种格式的文件和文档内容` —— 没触发场景，Claude 判断不出该不该加载

写 description 时问自己两个问题：
1. 用户会说哪些话？把**口语说法、别名、行业术语**都写进去
2. 有没有别的技能场景会被误触发？有就收紧措辞

## 正文结构四选一

| 结构 | 适合 | 骨架 |
|------|------|------|
| **工作流型** | 步骤清晰的过程 | 概述 → 决策树 → 步骤 1 → 步骤 2 … |
| **任务型** | 提供多种操作 | 概述 → 快速开始 → 任务 A → 任务 B … |
| **参考型** | 标准、规范、准则 | 概述 → 准则 → 规格 → 用法 |
| **能力型** | 相互关联的功能 | 概述 → 核心能力 → 1. … → 2. … |

可以混用。最常见的是**任务型打底 + 复杂操作补工作流**。
拿不准时用工作流型 —— 蒸馏出来的内容大多本身就有步骤。

## 渐进式披露

三级加载，越往后越省上下文：

| 层级 | 内容 | 何时进入上下文 | 大小 |
|------|------|---------------|------|
| 元数据 | name + description | **始终在** | ~100 词 |
| SKILL.md 正文 | 主流程 | 触发时加载 | <500 行 |
| references/ | 详细资料 | 按需加载 | 无上限 |

规则：
- **引用只保持一层深度**：`SKILL.md → references/foo.md`。不要 `references/foo.md → references/bar.md`
  （这条管的是**产物**；母体 skill 自己的 references 之间互相引用不受限）
- 超过 100 行的参考文件，**开头要有清晰的分级标题**（`##` 二级标题即可）；超过 250 行再加目录 —— 校验器强制检查前者
- 引用一律用**相对路径**（`references/foo.md`），不要写绝对路径

## 资源目录职责

| 目录 | 放什么 | 是否读进上下文 |
|------|--------|---------------|
| `scripts/` | 能跑就别让 Claude 现推的代码 | 否（直接执行） |
| `references/` | 需要读进上下文才能用的资料 | 是（按需） |
| `assets/` | 模板、字体、图标等产出物素材 | 否（用于生成输出） |

**不确定要不要拆，就别拆。** 一个 SKILL.md 能说清的事，不要建目录。

## 交付前检查

- [ ] `name` 与目录名一致，且只含小写字母 / 数字 / 连字符
- [ ] `description` 里别人一看就知道"什么时候该用它"，且没有尖括号
- [ ] 正文里没有解释 Claude 本来就知道的事
- [ ] 所有相对路径引用都能在磁盘上找到
- [ ] 没有残留 TODO、`[待填写]`、示例文件
- [ ] 通读一遍：一个没看过原文的人，照着能不能干活
